No se ejecutaron Lighthouse, axe, lectores de pantalla ni pruebas de teclado/dispositivo. SonarQube no se utiliza como certificado WCAG.

## 1. Resumen de Accesibilidad por Principios

Se conserva la revisión por principios y una matriz de hallazgos, sustituyendo porcentajes agregados por estados de criterios concretos:

- **Perceptible:** etiquetas visibles y contenido textual disponibles; requiere mejorar asociaciones semánticas y comprobar contraste y adaptación.
- **Operable:** navegación principal con botones nativos; existen interacciones personalizadas que requieren alternativa por teclado.
- **Comprensible:** módulos y acciones con nombres funcionales; reforzar identificación y comunicación accesible de errores.
- **Robusto:** mejorar nombres accesibles, semántica de modales y anuncios de cambios en web y móvil.

**Estados:** **Cumple** = evidencia suficiente para el aspecto concreto inspeccionado; **Cumple parcialmente** = existe soporte pero la evidencia es incompleta o mixta; **Requiere mejora** = barrera identificada en código. Estos estados se limitan a la muestra indicada; no equivalen a conformidad integral AA. Las comprobaciones sin ejecución se identifican expresamente.

### 2.1 Observaciones relevantes y recorridos de verificación

| Recorrido | Evidencia que debe conservar la siguiente validación |
| :--- | :--- |
| Login → navegación | Entrada válida e inválida, nombres anunciados, foco visible y acceso a módulos según rol |
| Clientes → Pedidos | Registro, edición, errores vinculados y selección de preferencias por teclado |
| Rutas → reoptimización | Consulta textual de paradas, operación del mapa, apertura/cierre de diálogo y anuncio del resultado |
| Admin → usuarios/permisos | Lectura de campos y roles, foco del modal, guardar/cancelar y notificación accesible |
| Móvil cliente → nuevo pedido | Lectura de controles y validaciones, escala de texto y operación sin gestos exclusivos |
| Móvil repartidor → detalle/entrega | Nombre de recarga/salida, secuencia de lectura, consulta de ruta y anuncio del estado de entrega |

En cada comprobación se registrarán commit, dispositivo/navegador, tecnología de asistencia, pasos, resultado y captura o registro correspondiente. Estos recorridos son un plan verificable de mejora continua y no evidencia de pruebas ejecutadas. La muestra no sustituye una auditoría completa de todos los criterios A y AA aplicables.

### Conclusión

El Sprint 3 conserva su **cierre satisfactorio al 30/10/2026**. No se declara conformidad integral WCAG 2.1 AA ni se confunde el cierre funcional con certificación de accesibilidad.
