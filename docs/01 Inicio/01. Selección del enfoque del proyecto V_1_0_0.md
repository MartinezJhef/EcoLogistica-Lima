## 2. Matriz de Ponderación de Variables

La selección del enfoque metodológico de gestión y desarrollo se fundamenta en la evaluación cuantitativa de las variables clave del proyecto, utilizando una escala Likert de 1 a 5.

Para interpretar el perfil metodológico:

- **1 a 2:** tendencia Predictiva, cuando las condiciones favorecen una planificación estable y un mayor control previo.
- **3:** tendencia Híbrida, cuando se requiere combinar planificación y adaptación.
- **4 a 5:** tendencia Ágil/Adaptativa, cuando existe complejidad, necesidad de retroalimentación continua o entregas frecuentes.

| ID | Variable de Evaluación | Ponderación (1 - 5) | Justificación Técnica y Análisis del Contexto |
| :---: | :--- | :---: | :--- |
| **VAR-01** | **Claridad y estabilidad de requisitos** | **3 / 5** | El objetivo general del proyecto está definido, pero los algoritmos de ruteo verde, las reglas ambientales y la integración con servicios geoespaciales pueden requerir refinamientos durante el desarrollo. Por ello, existe una condición intermedia entre estabilidad y evolución de requisitos. |
| **VAR-02** | **Complejidad técnica e innovación** | **4 / 5** | El proyecto integra aplicación móvil, panel web, geolocalización, optimización de rutas, cálculo de emisiones de CO₂, servicios cartográficos y sincronización de información. Esta complejidad requiere desarrollo incremental, experimentación y validación continua. |
| **VAR-03** | **Severidad del impacto ante cambios** | **2 / 5** | La arquitectura desacoplada permite aislar modificaciones en determinados componentes y disminuir el impacto global de cambios localizados. Esta condición favorece el control predictivo de componentes estables, aunque el desarrollo general mantiene capacidad de adaptación. |
| **VAR-04** | **Disponibilidad de los interesados (stakeholders)** | **4 / 5** | Se considera la participación continua del equipo docente, representantes de empresas de reparto, personal de despacho y conductores para realizar revisiones, validaciones y retroalimentación durante el desarrollo. |

### Resultado de la ponderación

$$
\text{Promedio} = \frac{3 + 4 + 2 + 4 + 5}{5} = \frac{18}{5} = 3.6
$$

> **Resultado:** Perfil metodológico **HÍBRIDO (3.6 / 5.0)**, debido a la combinación equilibrada de elementos predictivos y adaptativos presentes en el proyecto.

## 4. Decisión y Justificación del Enfoque

### 4.1. Declaración Explícita del Enfoque Seleccionado

Se selecciona oficialmente el **ENFOQUE HÍBRIDO (Predictivo - Adaptativo)** para la gestión y ejecución del proyecto **EcoLogistica-Lima**.

El enfoque híbrido permite combinar mecanismos de planificación y control predictivo con prácticas adaptativas para el desarrollo iterativo del producto de software.

### 4.2. Justificación Técnica Alineada al PMBOK® 7ª Edición

De acuerdo con el enfoque de desarrollo y cadencia de entrega planteado en el PMBOK® 7ª Edición, la selección del enfoque debe considerar las características del proyecto, su nivel de incertidumbre, complejidad, participación de interesados y necesidad de generar valor.

En EcoLogistica-Lima se establecen dos componentes de gestión complementarios:

#### 1. Componente Predictivo

**Control del plazo académico**

El proyecto dispone de un horizonte fijo de **16 semanas**, por lo que se requiere controlar hitos, entregables institucionales y fecha de presentación final.

**Gestión del alcance**

Se establecerá una línea base de alcance que permita identificar las funcionalidades comprometidas para el Producto Mínimo Viable, evitando incorporar cambios que comprometan la fecha de finalización.

**Gestión del costo**

El proyecto cuenta con un presupuesto máximo definido en el Acta de Constitución, por lo que los gastos deberán ser planificados, controlados y registrados durante la ejecución.

**Gobernanza y documentación**

Los documentos de gestión, arquitectura, requisitos, riesgos y evidencias deberán mantenerse bajo control de versiones y alineados con los hitos académicos.

#### 2. Componente Adaptativo / Ágil

**Desarrollo mediante Sprints**

El desarrollo del software se organizará en **8 Sprints de 2 semanas**, permitiendo planificar, desarrollar, probar y revisar incrementos funcionales.

**Refinamiento continuo de requisitos**

Las funcionalidades relacionadas con optimización de rutas, geolocalización, tráfico, emisiones de CO₂ y experiencia de usuario pueden requerir ajustes durante las validaciones, por lo que el Product Backlog podrá refinarse de manera controlada.

**Retroalimentación de stakeholders**

Las revisiones periódicas con los interesados permitirán validar los incrementos y detectar necesidades de mejora antes de la entrega final.

**Gestión de riesgos técnicos**

Los componentes de mayor complejidad, como el motor de optimización, integración geoespacial y sincronización entre plataforma web y aplicación móvil, serán desarrollados y validados progresivamente para reducir incertidumbre técnica.

### 4.3. Conclusión de la Selección

El **enfoque híbrido** se adopta porque el proyecto presenta simultáneamente:

- restricciones predictivas de tiempo, presupuesto, alcance y documentación;
- complejidad técnica que requiere experimentación e iteración;
- participación frecuente de stakeholders;
- necesidad de entregar incrementos funcionales durante el desarrollo.

Por ello, la gestión global del proyecto utilizará mecanismos de planificación y control predictivo, mientras que la construcción y validación del producto de software utilizará prácticas adaptativas mediante Sprints.
