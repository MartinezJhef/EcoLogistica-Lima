## 3. Justificación Técnica Formal

> **Declaración de Selección Tecnológica:**  
> El equipo de proyecto (**Zayuri Cerron, Jheferson Martinez, Angela Rojas, Maylit Mendoza y Diego Angulo**) selecciona oficialmente la **Alternativa B: Python / FastAPI + React + PostgreSQL / PostGIS** como el stack tecnológico oficial para el desarrollo e implementación de **EcoLogística Lima (PFA-ECOLIMA-2026)**, habiendo obtenido la calificación técnica más alta con **9.1 / 10**.

La decisión técnica se sustenta en los siguientes pilares de arquitectura e ingeniería:

1. **Optimización de Rutas y Algoritmos Verdes (CVRPTW):** La necesidad central del proyecto radica en calcular rutas óptimas de bajas emisiones de $CO_2$ considerando ventanas de tiempo y capacidad vehicular. Python ofrece una integración nativa con librerías científicas y de investigación operativa (Google OR-Tools, SciPy, NetworkX), evitando la necesidad de construir microservicios adicionales en otros lenguajes únicamente para el motor de optimización.
2. **Capacidades Geoespaciales y Datos Relacionales:** La combinación de **PostgreSQL con la extensión PostGIS** proporciona capacidades nativas para almacenar, consultar e indexar objetos geográficos (coordenadas de bodegas, clientes, geocercas de Lima Metropolitana y trazado de vías), garantizando la integridad transaccional ACID de las operaciones de despacho de *DistriRápido S.A.C.*
3. **Alto Rendimiento y Mantenibilidad con FastAPI:** Al estar basado en el estándar ASGI, FastAPI ofrece soporte asíncrono nativo con tiempos de respuesta reducidos ($<350\text{ ms}$ en endpoints de ruteo), autodocumentación bajo la especificación OpenAPI (Swagger UI) y validación estricta de datos de entrada con Pydantic.
4. **Criterios de Green Software e Infraestructura Cloud:** El stack elegido permite un despliegue desacoplado mediante contenedores Docker en arquitectura Serverless/PaaS. Esto optimiza el uso de CPU y memoria RAM bajo demanda, cumpliendo con los principios de bajo consumo energético (ISO 14083) y garantizando el control del presupuesto de **S/ 12,850.00 PEN**.
5. **Alineación con el Equipo y Plazo de 16 Semanas:** La utilización de React en la capa web complementa los conocimientos en JavaScript del equipo, mientras que Python centraliza el desarrollo backend y la lógica matemática, minimizando la curva de aprendizaje dentro del cronograma estricto de 8 sprints quincenales.

## 4. Consideraciones adicionales

### 4.1. Gestión de mapas y datos geográficos

El frontend web consumirá mapas interactivos mediante **Leaflet.js / React-Leaflet** sobre cartografía abierta de **OpenStreetMap (OSM)**. Para la matriz de distancias y cálculo de rutas en Lima Metropolitana, el backend interactuará con APIs de geolocalización y ruteo como **OSRM (Open Source Routing Machine)** o **GraphHopper**, implementando una capa de caché en memoria con **Redis** para mitigar la latencia y optimizar las peticiones recurrentes.

### 4.2. Aplicación móvil para conductores y trazabilidad

Para la aplicación móvil de los conductores (compatibilidad con Android 10+), se empleará un marco de desarrollo multiplataforma optimizado (**Flutter / React Native**), asegurando un bajo consumo de batería en el dispositivo móvil y la capacidad de operar bajo arquitectura *Offline-First* (almacenamiento local SQLite/Room) frente a caídas de conectividad en ruta.

### 4.3. Despliegue e infraestructura cloud

La solución adoptará una arquitectura de microservicios desacoplados empaquetados en contenedores **Docker**. El despliegue productivo se realizará en plataformas Cloud (AWS / Render / Supabase) aprovechando créditos educativos y capas gratuitas *PaaS*, garantizando auto-escalamiento horizontal, balanceo de carga y aislamiento de entornos (*Staging* y *Production*).
