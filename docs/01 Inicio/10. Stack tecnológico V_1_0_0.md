# 10. Stack Tecnológico y Arquitectura de la Solución

---

## 1. Evaluación de Alternativas de Stack Tecnológico


| Criterio de Evaluación | Alternativa 1: MERN (Node/Express + React + MongoDB) | Alternativa 2: Python / FastAPI + React + PostgreSQL | Alternativa 3: Java Spring Boot + Angular + PostgreSQL |
| :--- | :--- | :--- | :--- |
| **Curva de Aprendizaje** | **Baja — 9/10**. JavaScript puede utilizarse tanto en frontend como en backend, reduciendo la cantidad de lenguajes que debe dominar el equipo. | **Media — 7/10**. Requiere Python para backend y JavaScript para frontend, aunque FastAPI simplifica el desarrollo de APIs. | **Alta — 4/10**. La alternativa incorpora Java, Spring Boot y Angular, aumentando la cantidad de conceptos y tecnologías que debe dominar el equipo. |
| **Costo de Infraestructura** | **Moderado — 8/10**. Node.js utiliza un modelo basado en eventos y E/S no bloqueante, apropiado para aplicaciones web. | **Bajo — 9/10**. FastAPI está orientado a APIs de alto rendimiento y PostgreSQL es una tecnología open source. | **Alto — 5/10**. La JVM requiere considerar el consumo de memoria y la configuración del heap y garbage collection. |
| **Soporte Comunitario** | **Masivo / Muy Alto — 10/10**. Node.js, React y JavaScript cuentan con un ecosistema ampliamente utilizado. | **Alto / Crecimiento acelerado — 8/10**. Python cuenta con un ecosistema amplio y FastAPI presenta un crecimiento importante. | **Masivo / Corporativo consolidado — 10/10**. Java y Spring poseen una amplia adopción empresarial y un ecosistema consolidado. |
| **Eficiencia Energética / Eco-Design** | **Media — 7/10**. El modelo orientado a eventos y las operaciones I/O no bloqueantes pueden resultar eficientes para cargas orientadas a I/O. | **Alta — 9/10**. FastAPI utiliza ASGI y está orientado a servicios de alto rendimiento, aunque el consumo real depende de la carga y configuración. | **Media-Baja — 5/10**. La JVM administra memoria mediante heap y garbage collection, por lo que puede requerir mayores recursos en determinadas cargas. |
| **Integración con Algoritmos Metaheurísticos** | **Media — 5/10**. Es posible implementar algoritmos de optimización con JavaScript, pero el ecosistema científico es menor que el disponible en Python. | **Alta — 10/10**. Python dispone de un ecosistema amplio para computación científica, optimización, IA y algoritmos metaheurísticos. | **Medio-Alta — 7/10**. Java permite implementar algoritmos de optimización y dispone de bibliotecas especializadas. |
| **Soporte Geoespacial y GIS** | **Medio-Alto — 8/10**. MongoDB dispone de índices geoespaciales `2dsphere` y permite realizar consultas sobre información geográfica. | **Alto — 10/10**. PostgreSQL + PostGIS proporciona capacidades avanzadas para almacenar, consultar y procesar información geoespacial. | **Alto — 9/10**. PostgreSQL + PostGIS proporciona capacidades GIS avanzadas y puede utilizarse desde aplicaciones Java. |
| **Rendimiento de API y Concurrencia** | **Alto — 9/10**. Node.js utiliza un modelo de eventos y E/S no bloqueante adecuado para aplicaciones con numerosas operaciones I/O. | **Alto — 9/10**. FastAPI utiliza ASGI y permite desarrollar APIs con soporte para operaciones asíncronas. | **Alto — 9/10**. Spring Boot proporciona un ecosistema maduro para desarrollar aplicaciones y servicios concurrentes. |
| **Generación Automática de Documentación** | **Media — 6/10**. Express no genera por sí mismo documentación OpenAPI y normalmente requiere herramientas adicionales. | **Alta — 10/10**. FastAPI genera automáticamente documentación OpenAPI y proporciona Swagger UI y ReDoc. | **Medio-Alta — 8/10**. Spring puede utilizar herramientas como Springdoc para generar documentación OpenAPI. |
| **Compatibilidad con BD Relacional** | **Media — 6/10**. MERN utiliza tradicionalmente MongoDB, una base de datos NoSQL, aunque Node.js también puede trabajar con PostgreSQL. | **Alta — 10/10**. PostgreSQL es una base de datos relacional y dispone de múltiples herramientas de integración con Python. | **Alta — 10/10**. Spring Data JPA/Hibernate proporciona integración consolidada con bases de datos relacionales. |
| **Experiencia del Equipo** | **Media — 6/10**. Existe familiaridad con JavaScript, pero se requiere dominio específico de Node.js, Express y MongoDB. | **Alta — 8/10**. Python presenta mayor afinidad con las actividades de IA, optimización y procesamiento de datos del proyecto. | **Baja — 3/10**. El equipo presenta menor experiencia con Java, Spring Boot y Angular. |
| **Alineación con los Requisitos del Proyecto** | **Media — 6/10**. Puede implementar la solución y dispone de capacidades GIS, pero MongoDB no ofrece el mismo enfoque relacional y geoespacial integrado de PostgreSQL + PostGIS. | **Alta — 10/10**. Integra Python para IA y optimización, FastAPI para la API y PostgreSQL + PostGIS para información relacional y geoespacial. | **Alta — 8/10**. Cumple los requisitos mediante Spring Boot, PostgreSQL y PostGIS, aunque presenta menor afinidad con la experiencia del equipo. |
| **Puntaje Total** | **7.5/10 — Medio-Alto** | **9.1/10 — Alto** | **7.2/10 — Medio-Alto** |
