# 11. Base de Datos

## 1. Datos generales

Proyecto EcoLogística Lima, PFA-ECOLIMA-2026. Versión 1.1.0, 20/11/2026. PostgreSQL 16 con PostGIS en Neon. Esta revisión documenta las extensiones implementadas; el modelo inicial se conserva en V_1_0_0.

## 2. Modelo operativo

Usuarios, vehículos, conductores, clientes, pedidos, rutas y tramos mantienen sus entidades separadas. Los pedidos vinculan su ruta y, cuando corresponde, su cuenta de cliente. La ruta vincula vehículo y conductor; los tramos conservan secuencia, geometría vial y métricas estimadas.

La migración 006 incorpora la cola `route_updates`, las restricciones operativas y la jornada. Cada actualización tiene UUID, ruta, conductor, itinerario serializado, motivo, fecha UTC y confirmación UTC. Los dispositivos confirman recepciones; las revisiones pendientes se conservan en PostgreSQL.

## 3. Extensión de Sprint 4

| Tabla | Clave | Contenido y uso |
|---|---|---|
| `sustainability_settings` | `id` varchar(40) | JSON de factores, fuente, vigencia, precios y proyectos; fecha de modificación |
| `sustainability_snapshots` | `id` varchar(36), identificador de ruta | JSON de factores al iniciar ruta y acumulación del recorrido completado antes de reoptimizar |
| `sustainability_exports` | `id` varchar(36) | Propietario, tipo, estado, datos, error, PDF bytea y creación UTC |

El identificador de instantánea y el propietario de exportación son referencias lógicas gestionadas por la aplicación; la migración 007 no declara claves foráneas para ellas. Las exportaciones tienen índices de propietario y estado. No se describe una restricción SQL que el esquema no contiene.

## 4. Integridad y acceso

El servidor conserva factores históricos y no recalcula costos pasados con tarifas nuevas. Solo las rutas completadas entran en los totales. Un costo sin parámetros se identifica como no configurado. El trabajador reclama trabajos mediante bloqueo de fila; una interrupción revierte la transacción y permite reintentarlos. El PDF solo se descarga por su propietario autorizado o administración.

Fechas de operación y vigencia se interpretan con el calendario de Lima; timestamps de auditoría permanecen en UTC. No se guardan contraseñas en texto plano: se utilizan hashes PBKDF2. Las credenciales de Neon no forman parte del repositorio.

## 5. Migraciones y verificación

Aplicar `src/database/init.sql`, `scripts/006_sprint3_route_updates.sql` y `scripts/007_sprint4_analytics.sql` en ese orden. Las migraciones aditivas se probaron repetidas sobre una base desechable. No ejecutar el sembrado E2E sobre datos operativos. La regresión PostGIS forma parte de GitHub Actions.
